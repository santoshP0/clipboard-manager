STASH RELEASE INSTRUCTIONS
==========================

1. Pull or merge every change that should be included in the release.

2. Add concise, user-facing release notes to WHATS_NEW.txt.

3. Commit the application changes and release notes, then confirm that the
   working tree is clean:

   git status

   The release command stops if it finds uncommitted changes.

4. Run the release command with the next version number:

   npm run release -- 1.1.0

   Version examples:

   - Minor release: 1.1.0, then 1.2.0, then 1.3.0
   - Bug-fix release: 1.1.1, then 1.1.2
   - Major release: 2.0.0

5. Monitor the Release workflow:

   https://github.com/santoshP0/clipboard-manager/actions/workflows/release.yml


WHAT THE RELEASE COMMAND DOES
=============================

- Requires a clean main branch containing the latest origin/main.
- Validates the version number and WHATS_NEW.txt.
- Updates package.json, src-tauri/tauri.conf.json, src-tauri/Cargo.toml,
  src-tauri/Cargo.lock, and the version displayed inside the app.
- Runs lint, the production frontend build, and cargo check.
- Creates the release commit and annotated version tag.
- Atomically pushes main and the tag to GitHub.
- Starts the multi-platform GitHub Actions release build.
- Publishes installers for macOS, Windows, and Linux.
- Empties WHATS_NEW.txt only after the release tag is successfully pushed.
- Commits and pushes the empty WHATS_NEW.txt for the following release.

Tag-triggered workflows publish the release. Starting the workflow manually
creates a draft, allowing it to be used as a non-public build test.


IMPORTANT
=========

Running the release command performs Git commits, creates a tag, and pushes to
GitHub. Merely editing this instruction file or WHATS_NEW.txt does not publish
anything.
